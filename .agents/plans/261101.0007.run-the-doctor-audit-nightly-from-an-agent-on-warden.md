# Task Breakdown

## Overview

The owner wants the extraction rules checked every night without a person watching. On
hive-warden-01, a cron job of the agent account `buddy` starts daily at 03:00 GMT+5 plus a
random delay of up to 30 minutes. It runs Claude Code headless (`haiku`, effort `medium`) in the
beacon repository. The agent runs the doctor audit (`make audit`, i.e. `doctor audit --all`),
reads its output, and decides whether any extraction rule or script needs fixing. It reports
only when something does.

When Claude Code refuses because a usage limit is reached (for example the weekly limit), Jev
reads the output and decides that it is a limit refusal. The wrapper then records the reset
time from that message and skips every later run until the time has passed. No run is wasted
against a closed quota, and nothing alerts about it.

## Assumptions

- `doctor audit` needs no database or `.env`. It probes the seeded sources from
  `migrations/*.seed*.sql` against their live pages (`cmd/doctor/README.md`). Task 1 confirms
  this on warden, including whether any `fetcher_kind='chromedp'` source needs Chromium there.
- The run is advisory: the agent reads and reports, and it never edits, commits, or pushes.
  Fixes stay with a normal session, through `doctor rulegen` or a plan.
- The owner's time is 03:00 GMT+5. warden runs in UTC, and its cron (Ubuntu `cron` 3.0pl1)
  has no `CRON_TZ`, so the entry is `0 22 * * *` UTC. GMT+5 has no daylight saving, so the
  offset is fixed.
- Jev answers typed questions (`noul` gives a yes/no probability). It does not extract
  values, so the reset time is parsed from the message by the wrapper. Jev only decides
  whether the output is a limit refusal at all, which keeps the parser from acting on
  unrelated text.
- `jev-cli` runs through OpenRouter, which is prepaid. One `noul` call happens only when Claude
  Code exits non-zero, so the cost is negligible.

## Tasks

### Task 1: Prerequisites on warden (verify, record results here)
- Description: as `buddy` on hive-warden-01, confirm:
  - `make audit` succeeds from a clean checkout of `alpha` with no `.env`, and note the run
    time and whether a Chromium binary is needed and present;
  - `claude -p --model haiku --effort medium` runs non-interactively as `buddy` (no prompt,
    no login);
  - `tbot-cli` is on `buddy`'s `PATH` (`~/.local/bin/tbot-cli`) and has its `.env`; it is
    deployed by the owner's warden key script, which has not completed yet;
  - `jev-cli` from the `cli-jev` skill runs with its full path and finds the OpenRouter key in
    `~/.config/cli-openrouter/.env`;
  - the exact text and exit code Claude Code produces at a usage limit. Take a real sample
    from past session logs or the next occurrence. Keep the message, the reset time format
    and the time zone, and redact any account details.
    Known so far (mac-m1 session logs, three occurrences): `You've hit your limit · resets 3pm`,
    with no date and no time zone. The zone is the owner's GMT+5 (the time Claude Code shows
    follows the account's machine; confirm on warden), so the parser takes the next
    occurrence of that hour in GMT+5 and stores it in UTC.
- Acceptance Criteria:
  - Each point is recorded in this plan with its result; any blocker is resolved or handed to
    the owner before Task 2.
- Pitfalls & edge cases: the remote-projects SSH alias currently logs in as `seil`, not
  `buddy`; use `ssh hive-warden-01` with `sudo -u buddy -i`.
- Complexity: Easy

### Task 2: The nightly wrapper `.agents/scripts/doctor-nightly.sh`
- Description: one bash script, run by cron, that:
  1. sleeps a random 0–1800 seconds (`$((RANDOM % 1801))`);
  2. exits 0 if `~/.local/state/beacon-doctor/skip-until` holds a UTC time that is still in the
     future, logging one line;
  3. refreshes a dedicated detached worktree of the `buddy` beacon checkout at `origin/alpha`
     (`git fetch` plus `git worktree add --detach` or `git checkout --detach origin/alpha` in
     that worktree). It never touches the main checkout, where sessions may work;
  4. runs `claude -p --model haiku --effort medium --output-format json` in that worktree, with
     tools limited to `Bash(make audit:*)`, `Bash(make build:*)`, `Read`, `Grep` and `Glob`.
     The prompt says: run `make audit`, read the per-source result, and answer with
     `VERDICT: ok` or `VERDICT: fix` followed by the sources that MISS and the likely cause;
     edit nothing;
  5. writes the full output and the exit code to
     `~/.local/state/beacon-doctor/YYYY-MM-DD.log`, keeping the last 30 logs;
  6. on `VERDICT: fix`, or an audit infrastructure error, sends one Telegram message through
     `tbot-cli` with the verdict and the log path; on `VERDICT: ok`, stays silent;
  7. on a non-zero Claude Code exit, runs Task 3.
- Acceptance Criteria:
  - A dry run with a stubbed `claude` covers ok, fix, limit and failure paths.
  - Two overlapping runs cannot both proceed (`flock` on the state directory).
  - `shellcheck` is clean, and the project gate (`make test`) stays green.
- Pitfalls & edge cases: cron's minimal environment needs `PATH` to include
  `~/.local/bin` and Go; the script sets it. The worktree must be pruned if its directory is
  removed by hand.
- Complexity: Medium

### Task 3: Usage-limit detection with Jev and the skip window
- Description: when Claude Code exits non-zero, ask Jev with `noul`: "Does this Claude Code
  output report that a usage or rate limit was reached, so the request was refused?" Pass the
  last 2 KB of the output, and treat a probability of 0.8 or more as yes. On yes, parse the
  reset time with the formats recorded in Task 1, convert it to UTC, and write it to
  `skip-until`. On no, treat the exit as a failure and report it through Task 2 step 6.
- Acceptance Criteria:
  - Fixtures with the real limit message (Task 1), a plain error, and an audit failure produce
    yes, no and no.
  - A parsed reset time lands in `skip-until`, and the next run skips until then, then
    resumes and removes the file.
  - When Jev says yes but no reset time parses, the run logs it and writes nothing, so the
    next nightly run simply tries again. That attempt is the only retry.
  - When `jev-cli` itself fails, the run is reported as a failure; it is never read as a limit.
- Pitfalls & edge cases: time zones in the message (`resets 5pm (Asia/Almaty)`) versus host
  time; a reset time in the past (clock skew) is ignored; never send secrets or the full log
  to Jev, only the output tail.
- Complexity: Medium

### Task 4: Install the cron entry (owner-approved command)
- Description: `buddy`'s crontab gets one line:
  `0 22 * * * $HOME/.local/state/beacon-doctor/run.sh` (22:00 UTC = 03:00 GMT+5), where `run.sh` executes the
  wrapper from the dedicated worktree (or the line points at the worktree's
  `.agents/scripts/doctor-nightly.sh`). The crontab is outside the paths agents may write
  remotely without approval, so the exact command goes to the owner first.
- Acceptance Criteria:
  - `crontab -l` as `buddy` shows the line, and the first scheduled run leaves a log.
  - Reversal is documented: `crontab -e` removes the line, and the state directory can be
    deleted.
- Complexity: Easy

### Task 5: Document the job
- Description: add a row to the cron table in `cmd/doctor/README.md` (nightly agent audit on
  warden) and one line in `AGENTS.md` pointing at the script and its state directory.
- Acceptance Criteria: the documentation names the schedule, the host, the log location and
  how to pause the job.
- Complexity: Easy

## Risks

- `haiku` may misread an audit table. The verdict line is checked against the audit's own exit
  code: `make audit` exit 1 (MISS) with `VERDICT: ok` is reported as a disagreement.
- Live pages can fail transiently and cause false alarms. The audit already distinguishes
  MISS from infrastructure errors; a source that fails on one night only can be suppressed
  later if noise shows up, and is not designed in now.
- The limit message format may change with a Claude Code update. Jev's yes still stops a
  wasted retry loop, but parsing fails, so the run waits only until the next night.

## Trade-offs

- Advisory only versus letting the agent run `doctor rulegen`: rulegen rewrites
  `rate_sources` rows wholesale and calls paid AI providers, so an unattended nightly rewrite
  is out of scope. Reversal: widen the allowed tools and the prompt in a later plan.
- Jev plus a deterministic parser versus asking the model for the time: Jev returns
  calibrated yes/no only, and a regex keeps the stored time exact.
