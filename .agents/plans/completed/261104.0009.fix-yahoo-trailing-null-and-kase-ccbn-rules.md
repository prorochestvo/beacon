# Task Breakdown

## Overview

The first nightly audit on hive-warden-01 (plan 261101.0007, 2026-11-04T01:40Z) reported two
real extraction failures. The owner asked to fix them.

1. **Yahoo equities, `JSON_PATH_ERROR` x15.** The shared spark URL
   (`range=5d&interval=1d`) lists a bar for the next trading day before it trades, with a null
   close: `AAPL close [343.83, 348.91, 344.63, 338.32, null]`. The rules read `close[-1]`, so
   `ApplyJSONPath` returns a null terminal and fails. Crypto symbols are unaffected. Production
   collects equities around the clock, so values are lost while the placeholder bar is listed.
   Consumes backlog `261101.0007-261104.M.0008`.
2. **KASE CCBN, `REGEX_NO_MATCH`.** `kase.kz/en/investors/shares/CCBN` is now an Angular SSR
   page; the `class="last-deal"` markup the rule anchors on is gone. The page loads its deals
   from `https://kase.kz/api/instruments/last-deals/CCBN`, which returns a JSON array of the
   latest deals, newest first: `[{"deal_date":"2026-11-03T17:29:48",...,"price":5461.0,...}]`.
   Reachable from warden (HTTP 200, 0.5 s) without a proxy.

## Decisions

- **D1: a negative index skips null elements.** `close[-1]` already means "the newest close"
  (migration 202608.032); a null is not a close. Counting negative indices over non-null
  elements keeps every rule unchanged and fixes all 15 sources at once. Positive indices keep
  literal semantics. An array with too few non-null elements is an out-of-range error, as
  today. Alternative rejected: a new path syntax (for example `[last]`) would need a migration
  rewriting 20 rules for the same effect. Reversal: revert the extractor change.
  This reverses the stance of the subtest "a null at the end surfaces rather than being
  skipped" in `matchers_test.go`, written for the five-minute window: there a trailing null
  was a no-trade gap and failing let the next tick retry. Since 202608.032 the window is daily
  bars, a trailing null is a session that has not traded yet, it persists for hours, and the
  previous close is the current price until the session opens, the same staleness 202608.032
  already accepted for crypto at 00:00. The subtest is rewritten to assert the skip.
  Accepted consequences: a halted ticker whose recent closes are all null keeps reporting a
  price up to five days old and `SourceHealthAgent` no longer flags it (delta conditions stay
  quiet because the delta is 0; interval and daily digests show the old price). Negative
  indices address the Nth non-null element, so they are not positionally aligned across
  sibling arrays such as `close[-1]` and `timestamp[-1]`; no rule reads `timestamp` today.
- **D2: CCBN reads the JSON API with a regex.** The API root is an array, and `json_path`
  requires an object at the first segment. The regex `"price":\s*([0-9]+(?:\.[0-9]+)?)` takes
  the first `price`, which belongs to the newest deal. Extending `json_path` to address a root
  array is broader than needed. Reversal: a migration restoring the old URL and rule.
- **D3: staleness is accepted.** The API keeps the last session's deals, so on non-trading
  days the value is the last traded price, matching what the page shows. `interval` stays
  `6h`. Unverified: what the API returns before the first deal of a new session. If it is
  `[]`, the rule misses and health alerts after three 6 h ticks; accepted as a risk, the
  nightly audit would show it.

## Tasks

### Task 1: Negative JSON path indices skip nulls
- `internal/tools/rateextractor/matchers.go` `ApplyJSONPath`: for `seg.Index < 0`, walk the
  array from the end over non-null elements; for `seg.Index >= 0`, keep the literal index.
  The out-of-range error names the requested index, the length and the non-null count
  (`index -1 out of range for key "close" (len 2, 0 non-null)`). Update the comment there
  and on `pathSegment.Index`, including the sibling-array alignment note from D1.
- Tests in `matchers_test.go` (`TestApplyJSONPath_NegativeIndex`): rewrite the GAPPY subtest
  unconditionally (`require.NoError`, value `1`); add a mid-array null `[1,null,3]` (`[-1]` is
  `3`, `[-2]` is `1`), an all-null array being out of range with the non-null count in the
  message, and a positive index on a null element still failing; other subtests unchanged.
- End-to-end test in `rateextractor_test.go`: a stub HTTP server serving the batched spark
  shape (an equity with a trailing null and a crypto symbol), two sources on one URL, driven
  through the real extraction entry point; both store the last non-null close.

### Task 2: Migration re-pointing KZ_KASE_LAST_CCBN_KZT to the deals API
- `migrations/202611.036.rate_sources.kase_ccbn_deals_api.sql`: `UPDATE rate_sources SET url,
  rules WHERE name = 'KZ_KASE_LAST_CCBN_KZT' AND url = 'https://kase.kz/en/investors/shares/CCBN'`
  (the URL guard, as in 202608.032, keeps a later `doctor rulegen` fix from being
  overwritten). Only `url` and `rules` change; `kind`, `fetcher_kind`, `options`, `active`
  and `interval` stay; `rule_metadata` is reset to `'{}'` because the seed's metadata
  describes the HTML rule. Rule: `"price":\s*([0-9]+(?:\.[0-9]+)?)[,}]`, so an exponent or
  other unexpected format misses instead of truncating. Header comment with the evidence.
- Historical test `migrations/kase_ccbn_rules_test.go`: parses the UPDATE from the migration
  file, asserts the URL, unmarshals the rules (covering the SQL-string escaping), and runs
  them through `rateextractor` against a trimmed copy of the real response where
  `dirty_price` and older deals differ from the newest `price`; expects the newest price.
  An empty array `[]` and an exponent-form price both miss.
- Acceptance: `make test` green; `doctor audit --dsn` against a freshly migrated database
  reports both fixes OK (manual check on warden).
