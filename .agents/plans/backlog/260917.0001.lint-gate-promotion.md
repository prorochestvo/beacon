# CLAUDE.md keeps lint advisory for a backlog that no longer exists

**Status: open.** Raised 2026-09-17, neither accepted into a plan nor dropped. Severity P3 —
a documentation/process call, not a defect.

`CLAUDE.md` states: "**`make test` is the gate; `make lint-new` is advisory until the lint
backlog is cleared**". That wording was correct when it was written. Measured on 2026-09-14
before cutting `r_0.0.3-alpha.25`: `make lint` over the whole tree reports **0 issues**, and
`make lint-new` likewise. The debt the sentence defers to is gone, so the file now documents
a state the repository is not in.

Worth deciding, one of:

- **Promote lint into the gate.** `make lint` already runs on every release tag (the
  `lint-and-test` job in `release.yml` lints the whole tree, not the diff), so a release
  already fails on a lint finding — the gate wording is behind what CI actually enforces.
  Making it explicit costs nothing today and stops the tree drifting back.
- **Keep it advisory and reword.** If the intent is that lint findings should never block a
  merge, say that instead of citing a cleared backlog.

Either way the sentence changes; leaving it as is means the next reader defers to a backlog
that is empty.
