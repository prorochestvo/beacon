# Yahoo spark equity rules fail on a trailing null close

**Status: open.** Raised 2026-11-04 by the first manual nightly run of plan 261101.0007.
Severity P2.

At 01:40 UTC the run reported `JSON_PATH_ERROR` for all 15 `US_YAHOO_LAST_*_USD` equity
sources on the shared `v8/finance/spark?...&range=5d&interval=1d` URL; the five crypto
symbols on the same URL were OK. A direct fetch at the same time returned
`AAPL close [343.83, 348.91, 344.63, 338.32, None]`: Yahoo already lists a bar for the next
trading day with a null close, so the rule's `close[-1]` resolves to null.

Migration `202608.032.rate_sources.spark_daily_window.sql` documents the null-array case for
continuously traded symbols but not a trailing null element inside the array. Production
collection runs at every hour, so equity values are probably missing during the window in
which Yahoo shows the placeholder bar. The nightly audit runs at 22:00 UTC, after the US
close, and may not see it.

Worth deciding: check equity gaps in `rate_values` from a production snapshot, then either
let the JSON path skip trailing nulls (newest non-null close) or accept the gap.
